# 五能力模型 · 边界对抗检查方案（子 Agent 迭代准备）

> 目标：不挑战公理，只检查推导——发现子能力归属矛盾、概念吞并、同义改写和无法指导行动的模糊地带。
> 输入文档：`AI时代个人五能力模型.md`（公理与定义已锁定）
> 版本：2026-09-26 更新——停止条件节补入"轴稳定三特征"（B8 对照组产出，经用户确认追加）；八条边界已全部完成迭代

---

## 一、迭代协议（每轮固定）

### 角色分工

| 角色 | 职责 |
|---|---|
| 建模 Agent | 分别从边界两侧能力的立场解释同一场景，各自提出应纳入的子能力 |
| 反驳 Agent | 专门攻击：定义循环、概念吞并、遗漏场景、无法区分的反例、"万能概念" |
| 测评 Agent | 检验两侧解释能否转化为可观察的个人行为，而不只是文字上不同 |
| 主控 | 按裁决标准综合，填写边界记录卡，决定是否修改模型文档 |

### 裁决标准

1. 能否解释真实个人行为；
2. 能否形成可观察的自检指标；
3. 是否出现"万能概念"（重点盯元认知、系统治理）；
4. 是否与其他能力已有子能力重复或同义改写；
5. 删除该子能力后是否出现实际覆盖缺口。

### 硬纪律

- **三场景晋升规则**：候选子能力须在 ≥3 个性质不同的场景中复现，且不能被现有子能力解释，才写入模型；
- **元认知拒绝清单**：涉及元认知的每轮迭代，必须列出"本轮拒绝纳入元认知的内容"；
- **允许重叠，不允许模糊**：交叉内容必须给出"主要归属＋次要关联＋最终落点"，判不出来的记入"未解决问题"；
- **回归测试**：每次修改模型文档后，用全部旧场景重新诊断，不得出现新的解释失败。

### 边界记录卡模板

```text
边界组合：
争议场景：
能力A的解释：
能力B的解释：
主要判别轴：
主要归属：　次要关联：　最终落点：
不能归入A的部分：
不能归入B的部分：
可观察行为（个人自检指标）：
反例：
元认知拒绝清单（如适用）：
未解决的问题：
对模型文档的修改：
```

### 停止条件

- 新一轮没有产生无法归属的重要场景；
- 每条边界有稳定判别轴＋至少 1 个反例通过测试——**"轴稳定"的可操作定义（轴稳定三特征，B8 对照组产出）**：
  1. **四象限可填充**：两侧强弱四种组合均有真实场景（存在"强×弱"错位象限，证明两侧可独立变化）；
  2. **观察对象类型不同**：两侧观察的是不同种类的东西（如文本质量 vs 流程事实），不需内省即可区分；
  3. **同框动作切口平整**：两侧同框的单一动作能一刀切开，切完无第三种残渣；
- 每条子能力有个人可自检的行为指标；
- 新增内容连续一轮全是同义改写。

> 用途：新边界或新判别轴先过三特征，过不了说明切分有问题（一、二不过＝两侧未真正分开；三不过＝存在无法归属的残渣）。内部双构造边界（如 B6）不适用，其判据为分开评分。

## 二、八条边界清单（按风险排序，即迭代顺序）

> 状态：B1–B8 全部完成对抗迭代并落文档（2026-09-26 定稿）。以下保留原始清单作为历史记录。

### B1 元认知 ↔ 逻辑判断 ｜ 吞并风险：★★★★★ ✅ 已完成

- **候选判别轴**：对内监控"我是否有资格相信" ↔ 对外分析"结论是否成立"。
- **争议焦点**："识别 AI 幻觉"归谁？——预期裁决：**验证答案真伪**（证据核查、交叉验证）→ 逻辑判断；**知道自己何时容易轻信、决定要不要验证** → 元认知。
- **种子场景**：AI 给出流畅的专业答案，用户该信吗？
- **反驳 Agent 攻击点**："判断自己的判断是否可靠"——这句话两侧都能认领，必须切开。

### B2 元认知 ↔ 沟通表达 ｜ 吞并风险：★★★★ ✅ 已完成

- **候选判别轴**：认识自己的状态 ↔ 让彼此形成正确理解。
- **争议焦点**："给 AI 写 prompt 前先得弄清自己要什么"——弄清意图是元认知还是沟通中的意图识别？
- **种子场景**：反复改 prompt 都得不到想要的结果。
- **反驳 Agent 攻击点**："自我澄清"链条（先对自己澄清、再对 AI 表达）不能整条归给任何一侧。

### B3 元认知 ↔ 协作编排 ｜ 吞并风险：★★★ ✅ 已完成

- **候选判别轴**：个人依赖状态的校准 ↔ 多方行动的组织。
- **争议焦点**："决定什么由人做、什么由 AI 做"在元认知（授权程度）、编排（人机分工）、治理（分工规则）三处都出现，必须按层级切开：当下自我依赖校准 → 元认知；为具体任务设计分工 → 编排；固化为长期规则 → 治理。
- **种子场景**：把核心判断逐步外包给 AI，自己变成"点确认键的人"。
- **反驳 Agent 攻击点**：三处"人机分工"表述是否同义改写。

### B4 元认知 ↔ 系统治理 ｜ 吞并风险：★★★ ✅ 已完成

- **候选判别轴**：监控状态 ↔ 建立机制（个人校准回路 vs 系统约束回路，两者同构但层级不同）。
- **争议焦点**：给自己定"AI 代码必须人工 review 才可合并"——定规则 → 治理；意识到自己最近没执行 → 元认知。那"决定要不要定这条规则"归谁？
- **种子场景**：AI 生成代码直接上线导致事故后的复盘。
- **反驳 Agent 攻击点**：个人 SOP 的"制定—执行—监控"全周期被单侧认领的风险。

### B5 逻辑判断 ↔ 系统治理 ｜ 吞并风险：★★★ ✅ 已完成

- **候选判别轴**：形成方案与结论 ↔ 固化为机制与规则（单次验收标准 → 逻辑；可重复质量门 → 治理）。
- **争议焦点**："系统理解"（组件、依赖、反馈）是治理子域还是逻辑判断的结构化分析？
- **种子场景**：设计个人"AI 产出复核清单"——第一次设计 vs 长期执行。
- **反驳 Agent 攻击点**：治理内容体量本来就最大，防止它继续吞并"系统设计"。

### B6 协作编排内部：关系协作 ↔ 任务编排 ｜ 失真风险：★★★ ✅ 已完成

- **候选判别轴**：信任、利益与冲突的协调 ↔ 任务结构与流程的设计。
- **争议焦点**：双构造测量失真——擅长多 Agent 编排但不擅处理人际冲突的人，如何评分？预期裁决：两个子维度**分开评分**。
- **种子场景**：个人同时管理 3 个 AI 工具 + 1 个人类合作者。
- **反驳 Agent 攻击点**："对 AI 的信任校准"是关系协作还是元认知？（预期：归元认知，关系协作只管人际。）

### B7 协作编排 ↔ 系统治理 ｜ 吞并风险：★★ ✅ 已完成

- **候选判别轴**：管理依赖关系 ↔ 管理权力、规则、风险与责任（**不用**"当前一次 vs 长期重复"——临时项目也需要治理）。
- **争议焦点**：临时个人项目里的权限设置（"数据不出本地"）归治理，无论项目多短。
- **种子场景**：用三个 AI 工具接力完成一个含敏感数据的项目。
- **反驳 Agent 攻击点**：检查是否有场景真正无法用这条判别轴区分。

### B8 沟通表达 ↔ 协作编排 ｜ 吞并风险：★（边界最稳，最后做）✅ 已完成

- **候选判别轴**：形成正确理解 ↔ 形成共同行动。
- **争议焦点**：多工具串联时"定义每一步的输入输出"——接口内容的清晰度 → 沟通；接口的存在与结构 → 编排。
- **种子场景**：写一段给 AI 的中间产物格式约定，供下一个工具使用。
- **反驳 Agent 攻击点**：作为对照组，验证"判别轴稳定"长什么样，反哺其他边界的记录卡。
