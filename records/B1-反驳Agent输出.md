# B1 边界对抗 · 反驳 Agent 输出

> 边界：元认知 ↔ 逻辑判断
> 攻击对象：预期裁决（验证真伪→逻辑判断；决定要不要验证→元认知）、候选判别轴（对内监控 ↔ 对外分析）、建模 Agent 双侧解释（`B1-建模Agent输出.md`）
> 纪律声明：不挑战公理与锁定定义（检查方案第 4 行："公理与定义已锁定"）；攻击目标仅限子能力归属、判别轴与推导一致性。所有攻击均附场景或文档原文；攻击失败处明确报告。

## 一、攻击预期裁决（靶子：验证真伪→逻辑；决定要不要验证→元认知）

### 命中 1-1｜专家瞬时核验：决策点根本不存在，归属结论依赖一个未发生的事件

**场景**：资深药剂师让 AI 整理一份药物相互作用清单，阅读第一眼就发现 AI 把华法林与某抗生素的禁忌方向写反了。核验在**阅读理解的同时**自动完成——没有"我此刻把握多大、要不要验证"的权衡，没有任何可指认的元认知动作。

**攻击**：
- 按预期裁决，该片段 100% 归逻辑判断，元认知零参与。但模型文档负效应表（第 20 行）将"把流畅的答案当成正确的答案 → 元认知：置信度超过证据，**未做验证**"——文档立场暗示"验证与否"场景必含元认知成分。裁决与锁定文档对同构场景给出不同诊断。
- 更荒谬的是反向情形：若药剂师**没看出来**而采信，事后归因是什么？不是"轻信倾向未监控"（她是本领域最高权威，监控结论会是"我有资格信"），而是"证据核查未启动"——但核查未启动恰恰是因为**决策点从未出现**。预期裁决把归属挂在"决定要不要验证"这个事件上，而该事件在专家场景、熟练场景中经常不存在。**裁决无法执行：它要求对一个未发生的动作做归属。**

### 命中 1-2｜习惯性验证：触发源是规则，裁决与模型文档的治理条目正面冲突

**场景**：用户半年前给自己定下铁律"AI 给的任何引用必须点开原文"，已固化为个人 SOP。本次他照旧点开核查，全程无自我状态监控、无风险权衡——只是执行规则。

**攻击**：
- 预期裁决："决定验证" → 元认知。
- 模型文档第 78 行：系统治理子能力含"**复核与质量门 · 个人 SOP**"；第 94 行进一步明确"固化为可重复的质量门 → 系统治理"。
- 同一次"决定验证"，B1 预期裁决判给元认知，模型文档既有推导判给系统治理——**跨边界矛盾（与 B4/B5 边界打架）**。若按裁决执行，则每次执行复核规则都要记一笔元认知，元认知反过来吞并治理的"复核质量门"执行层；若按文档执行，预期裁决错。**二选一，裁决错的那半边必须修。**

### 命中 1-3｜验证决策没有独立内容：它只是逻辑判断输出的"二传手"

**场景**：用户读 AI 给出的法律建议，心想"要不要花钱找律师核实？"。这个决定完全由两个输入决定：(a) "现有证据够不够"——证据充分性判断，模型文档第 50 行明确为逻辑判断既有子能力"**证据质量判断**"；(b) "出错的代价"——风险权重。其中 (a) 是纯粹的对外证据分析。

**攻击**：预期裁决把整条决策划给元认知，等于要求个人**先完成逻辑判断（证据充分性评估），再把结论搬进元认知做决策**。决策点自身没有独立于逻辑输出的内容。建模 Agent 自己在争议区②⑨承认这一点（第 43 行："若把'决定要不要验证'整条划给元认知，逻辑判断的'证据充分性判断'就被切走一半"；第 177 行："再次印证决策点是双层结构"）。**裁决无法执行：个人自检时无法区分"我在做元认知决策"与"我在复述逻辑结论"，自检指标（裁决标准第 2 条）失效。**

**本节结论**：3/3 攻击命中。预期裁决在标准场景（S1 新手面对陌生答案）方向正确，但在①决策点不存在、②触发源为规则、③决策内容为证据判断 三类场景中给出荒谬或自相矛盾的归属。**裁决需修正，不可原样接受。**

## 二、攻击判别轴（对内监控"我是否有资格相信" ↔ 对外分析"结论是否成立"）

### 命中 2-1｜回音室场景：分析对象同时是"我的"和"AI 的"，轴失去判别力

**场景**：用户先自行形成观点"远程办公提高团队产出"，再问 AI，AI 表示赞同并给出三条理由。用户信心大涨，准备据此向老板提案。此刻需要的检查是："这三条理由成立吗？"

**攻击**：
- 按轴字面问"对象方向"：对象是 AI 的输出（对外），内容却是用户自己的先验结论被原样送回（对内）。"结论是否成立"中的结论**就是我的结论**——此时"我是否有资格相信它"与"它是否成立"是**同一个问题**：一个我自己的结论，不存在"成立但我没资格信"或"不成立但我够资格信"的分离空间。轴的两极在此合并，无法判别。
- 两侧解释同样合理：元认知认领"觉察'被附和'带来的信心膨胀"（自我倾向监控，合理）；逻辑判断认领"核查三条理由的证据与推理"（内容核查，合理）。注意：**这不是轴判别成功了，而是两个不同的问题各自归侧**——轴对"用户信心大涨该不该信"这**一个**动作没有给出唯一答案。
- 该场景不是边缘案例：AI 的谄媚性（sycophancy）是当前最高频的轻信来源之一，轴在最高频场景失效。

### 命中 2-2｜"判断自己的判断是否可靠"：轴的字面归属与锁定定义直接冲突

**场景**：用户上午自己写了一份投资分析，睡前复查："我上午的结论可靠吗？"——重新检查证据链、寻找反例、校验推理跳跃。

**攻击**：
- 按轴字面：对象是"我自己的判断" → 对内 → 归元认知。
- 但模型文档锁定定义（第 46 行）：逻辑判断是"依据逻辑、证据、反例和边界条件**形成、验证和修正判断**"——验证和修正（包括自己的）判断是逻辑判断**定义内**的行为。第 50 行子能力"识别隐含前提与逻辑跳跃 · 反例与边界条件"均不以"对象是他人的结论"为限。
- 轴的字面应用把整个二阶校验动作划给元认知，**直接违背锁定定义**。定义锁定优先于候选判别轴，故轴必须让路。建模 Agent 在 6.4#4 试图用"元认知只管状态与倾向，不管推理内容本身"来补救——**这实际上已经更换了判别轴的判据**（从"对象方向"换成"内容 vs 状态"），恰好证明原轴表述不可维持。

### 攻击失败报告（同样重要）

以下构造方向**未能**撼动判别轴，如实报告：
1. **纯状态监控**："我注意到我赶 deadline 时容易照单全收"（S-D 第 157 行）——对象明确是自己的情绪/情境状态，轴判归元认知，干净。
2. **纯外部核查**："AI 说某药剂量是 10mg，我去查说明书"——对象明确是外部断言，轴判归逻辑，干净。
3. **疲劳/权威崇拜等倾向的觉察**——轴判别无歧义。

即：轴在**对象归属无歧义**的场景（外部 AI 输出 vs 内部情绪状态）判别力良好；失效集中在**对象自指**（自己的结论、被 AI 回音放大的自己的结论）。**轴的内核可用，表述必须修。**

## 三、吞并检查

### 命中 3-1｜"识别 AI 幻觉与流畅性误导"（元认知既有子能力，第 40 行）与建模 Agent 切分正面矛盾

- 建模 Agent 的切分（第 42、224 行）：幻觉识别 = 倾向监控（→元认知）＋ **核查执行（→逻辑判断）**。
- 但模型文档原文写的是"**识别** AI 幻觉与流畅性误导"，且负效应表（第 20 行）把"把流畅答案当正确答案"的缺失诊断为"元认知：**未做验证**"——两处都把**核查/验证动作整体**放在元认知名下。
- 矛盾不可调和：要么模型文档这条子能力**吞并了逻辑判断的"证据质量判断"**（核查一个断言是否属实，与核查任何证据是否充分，是同一个行为——建模 Agent 自己在第 215 行承认其候选 L9"AI 输出断言拆解与交叉核验"只是"L5 的 AI 场景特化"，即承认核查行为属逻辑侧）；要么建模 Agent 的切分违背锁定文档。因子能力属可修改的推导内容而切分逻辑自洽，**判定：模型文档该条目构成吞并，须改写**——元认知侧只保留"觉察自己易被流畅表达误导的倾向"，核查执行明确让渡给逻辑判断。

### 命中 3-2｜"置信度与证据匹配"（第 40 行）吞并"证据质量判断"的证据侧

"匹配"需要两端：我的置信度（对内，元认知合法）＋ **证据有多强**（对外，第 50 行逻辑判断"证据质量判断"的定义内行为）。条目按现状写法，证据侧整段落入逻辑判断领地。建模 Agent 的"置信一侧／充分性一侧"劈分（第 23、32 行）是唯一自洽解，但这等于承认**原条目表述是吞并性的，须加限定词**。

### 反向检查（逻辑判断是否吞并元认知）：未发现实质性吞并

逻辑判断九条子能力（第 50 行）全部以"问题/证据/推理/方案"为对象，未越界进入"自我状态监控"。唯一擦边是"设计验收标准与验证实验"与治理"复核与质量门"的关系，属 B5 边界，不在本轮范围。**反向吞并：攻击失败，如实报告。**

## 五、定义循环检查

### 命中 5-1｜两项能力的"核心问题"互为定义项

- 元认知核心问题（第 38 行）："我是否**正确**认识了自己、AI 和当前任务的边界？"——"正确"的判定标准 = 结论/认识是否成立 = 逻辑判断核心问题（第 48 行："证据和推理是否足以支持当前结论"）。**元认知的"校准"必须用逻辑判断的"成立"来定义。**
- 逻辑判断核心问题（第 48 行）："问题是否被**正确理解**"——"理解是否到位"的判定 = 元认知定义（第 36 行）"校准**理解程度**与置信度"。**逻辑判断的"正确理解"必须用元认知的"理解校准"来定义。**
- 循环闭合：A（元认知）的校准标准由 B（逻辑）供给；B 的理解正确性由 A 供给。因定义已锁定，**循环无法在定义层消除，只能靠判别轴在行为层打断**——这使"判别轴必须在行为上可执行"从"期望"升级为"硬性约束"。而第二节已证明现轴在自指场景行为层失效，故循环在此转化为实质缺陷。

### 命中 5-2｜"识别 AI 幻觉" ↔ "设计验收标准"的相互依赖

- 元认知"识别 AI 幻觉"（第 40 行）预设了"何为幻觉"= 未通过证据核查的断言 → 依赖逻辑的"证据质量判断"（第 50 行）。
- 逻辑"设计验收标准与验证实验"（第 50 行）用于 AI 输出时，验收标准的内容（要查幻觉、要查遗漏、要查逻辑变形）来自对 AI 失效模式的认知 → 依赖元认知定义中"识别……AI 的……能力……状态"（第 36 行）及建模 Agent 的争议区⑩（第 178 行）。
- 相互依赖成立，但属"输入互供"而非严格同义循环，严重程度低于 5-1。

## 六、总判决

### 预期裁决：**修正**（不接受、不推翻）

**保留的内核**：核查执行（断言拆解、交叉验证、原文比对、测试构造）→ 逻辑判断。该内核在全部场景中无反例。

**修正内容**："决定要不要验证 → 元认知"改为**按触发源三分**：
1. 触发源为**当下自我状态/风险的校准**（"我此刻容易轻信""这次出错代价我承担不起"）→ 元认知；
2. 触发源为**既有规则/SOP**（"我定了规矩必须核查"）→ 系统治理（与第 78、94 行对齐，消除命中 1-2 的跨边界矛盾）；
3. **无独立决策点**（核验随阅读理解自动发生，专家场景）→ 整个片段归逻辑判断，不强制归属元认知（消除命中 1-1）；
4. 决策的**证据充分性输入**（"现有证据够不够"）→ 逻辑判断"证据质量判断"，决策的**风险-状态权衡** → 元认知；二者在个人行为上以"先逻辑评估、后元认知权衡"的次序呈现，而非同一动作劈半（缓解命中 1-3，最终可分离性交测评 Agent 检验）。

### 判别轴：**修正表述，保留内核**（不更换）

**修正后的判别轴（替代方案）**：
> **分析内容 → 逻辑判断；监控状态 → 元认知。**
> 凡分析断言、证据、推理链、边界条件——**无论该结论来自 AI、他人还是自己**——归逻辑判断；凡监控自己的知识边界、置信倾向、情绪状态、依赖与授权程度——归元认知。
> 助记（不可作判据）：逻辑问"这东西对不对"，元认知问"我这个人此刻靠不靠谱"。

**修正理由**：原轴的"对内/对外"以**对象的所有权**为判据，在对象自指（自己的结论、AI 回音）时两极合并（命中 2-1），且与锁定定义"验证和修正判断"冲突（命中 2-2）。新轴以**问题类型**（内容 vs 状态）为判据，在全部旧场景回归：S1、S-A、S-B、S-C、S-D 的既有归属全部不变（建模 Agent 各场景交界线本质上都已是"内容 vs 状态"切法，如第 38、74、107、141、173 行），且命中 2-1、2-2 的场景获得唯一解：回音室中"核查三条理由"→逻辑，"觉察被附和的信心膨胀"→元认知；睡前复查自己的投资分析→逻辑（修正判断，定义内），"觉察自己当时是否急于下结论"→元认知。

### 对模型文档的修改建议（供主控）

1. 第 40 行"识别 AI 幻觉与流畅性误导" → 改写为"**觉察自己易被流畅表达误导的倾向**"（核查执行让渡逻辑侧，呼应命中 3-1、R-1）。
2. 第 40 行"置信度与证据匹配" → 加限定："**置信度与证据的匹配（置信校准一侧）**"（呼应命中 3-2、R-2）。
3. 第 20 行负效应表"未做验证"的元认知标注 → 改为"**未触发验证**（验证执行缺失归逻辑判断）"，消除与命中 3-1 的同源矛盾。
4. 边界判别表（第 88 行）B1 轴 → 替换为修正后表述。
5. 元认知拒绝清单确认：本轮拒绝将"证据核查执行""AI 断言拆解""验收标准设计"纳入元认知——与建模 Agent 拒绝清单（第 201 行）一致，**但拒绝清单本身也暴露了现有条目（识别幻觉、置信度匹配）与清单的冲突，证实第 1、2 条修改的必要性**。
